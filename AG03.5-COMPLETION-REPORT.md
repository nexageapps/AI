## 📊 Key Patterns Taught

### 1. Error Handling Pattern
```python
@tool
@safe_tool_execution
def my_tool(param: str) -> Dict:
    if not validate(param):
        raise ValidationError("...")
    # ... tool logic
```

**Result:** Structured errors that agents can understand and recover from

### 2. Rate Limiting Pattern
```python
limiter = RateLimiter(max_calls=5, time_window=10)

@tool
def rate_limited_tool(query: str) -> str:
    if not limiter.allow_call():
        return "Error: Rate limit exceeded"
    # ... tool logic
```

**Result:** API cost control (can save 50-90% on high-traffic tools)

### 3. Metrics Pattern
```python
@tool
@instrumented_tool
def monitored_tool(param: str) -> str:
    # ... tool logic
    # Automatically tracks: call count, duration, error rate
```

**Result:** Observability for production debugging

### 4. Parallel Execution Pattern
```python
# Prompt engineering approach
prompt = "Get user profile, orders, and reviews simultaneously"
# Agent calls all 3 tools in parallel → 1s vs 3s
```

**Result:** 3x performance improvement

### 5. Tool Composition Pattern
```python
@tool
def composite_tool(param: str) -> str:
    # Step 1: Validate
    validate_tool(param)
    # Step 2: Fetch data
    data = fetch_tool(param)
    # Step 3: Process
    return process_tool(data)
```

**Result:** Complex tools built from simple, testable components

## 🎓 Teaching Notes

### Common Student Questions

**Q: When should I use Pydantic vs simple type hints?**  
A: Pydantic for objects with validation logic. Simple types for primitives.

**Q: How do I prevent LLM hallucination?**  
A: Use `Literal` types, provide examples, validate outputs.

**Q: Should I retry on all errors?**  
A: No. Retry on transient errors (network, rate limit). Don't retry on validation.

**Q: How many tools is too many?**  
A: >20 tools and LLMs struggle. Use tool composition.

**Q: How do I test tools without the agent?**  
A: Call tools directly in unit tests. Test schemas with Pydantic.

### Teaching Tips

1. **Emphasize the "Why":** Every pattern solves a real production problem
2. **Show Failures First:** Let students see tools break, then fix them
3. **Build Incrementally:** Start with simple tool, add patterns one by one
4. **Use Real Examples:** E-commerce, banking, booking (relatable domains)
5. **Celebrate Wins:** Highlight performance improvements (3x speedup!)

### Office Hours Support

Common issues and fixes:
- **Pydantic validation errors:** Check import versions, Python 3.11+
- **Parallel execution not working:** Use GPT-4 or Claude 3+ (not 3.5)
- **Rate limiter issues:** Understand token bucket algorithm
- **Metrics not tracking:** Check decorator order (@tool → @instrumented_tool)
