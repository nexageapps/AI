## Content Breakdown

### Part 1: Tool Schema Design (1.5h)
- Literal types for fixed choices
- Pydantic models for validation
- Arrays and nested objects
- Best practices and anti-patterns

**Example:** E-commerce order with line items, each validated for product ID, quantity (1-100), and optional notes.

### Part 2: Error Handling (1.5h)
- Custom exception hierarchies
- Safe execution wrappers
- Retry logic with exponential backoff
- Validation at schema level

**Example:** Database query tool that distinguishes between "not found" (recoverable) and "internal error" (fatal).

### Part 3: Parallel Function Calling (1h)
- When LLMs call functions in parallel
- Independent vs dependent operations
- Handling partial failures
- Performance benchmarks

**Example:** Fetching weather, population, and timezone for a city (1s total vs 3s sequential).

### Part 4: Debugging (1.5h)
- Common failure modes (hallucination, silent errors)
- Logging all function calls
- Schema validation testing
- Context debugging

**Example:** Restaurant booking tool with 8 validation bugs fixed.

### Part 5: Production Patterns (1.5h)
- Token bucket rate limiter
- TTL cache implementation
- Metrics tracking (calls, duration, error rate)
- P95 latency monitoring

**Example:** API call rate limited to 5 calls/10 seconds with cache layer.

### Part 6: Advanced Patterns (1h)
- Streaming large datasets
- Tool composition (building complex tools from simple ones)
- Context-aware tools (authentication, state)

**Example:** Shopping cart that requires login before allowing add_to_cart.

### Part 7: Case Study (30m)
Complete e-commerce system with:
- Product search and inventory management
- Order creation with validation
- All production patterns integrated
- End-to-end testing

**Deliverable:** Working agent that handles 5+ edge cases gracefully.

## Exercises

### Exercise 1: Banking Agent (2h)
Build tools for:
- `check_balance(account_id)` with validation
- `transfer_funds(from, to, amount)` with funds check
- `get_transaction_history(account_id, days)` with filtering

**Skills:** Schema design, validation, error handling, rate limiting, metrics

### Exercise 2: Debug Buggy Tool (30m)
Fix a restaurant booking tool with:
- No date/time validation
- No availability check
- No error handling
- Poor return format

**Skills:** Debugging, validation, error handling, structured responses

### Exercise 3: Optimize Parallel Execution (1h)
Refactor sequential user data fetching (profile, orders, reviews) to parallel.

**Goal:** 3s → 1s latency reduction

**Skills:** Performance optimization, parallel execution, prompt engineering
