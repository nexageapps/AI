## Function Calling Patterns Cheat Sheet

### 1. Complex Schema Design

```python
from pydantic import BaseModel, Field
from typing import Literal, Optional, List

class OrderRequest(BaseModel):
    customer_id: int = Field(gt=0, description="Customer ID")
    items: List[Dict] = Field(description="Order items")
    shipping: Literal["standard", "express"] = "standard"
    notes: Optional[str] = Field(None, max_length=500)
```

**When to use:** Tools with multiple parameters, validation rules, or complex objects

### 4. Rate Limiting

```python
limiter = RateLimiter(max_calls=10, time_window=60)

@tool
def rate_limited_tool(query: str) -> str:
```

### 5. Caching

```python
cache = TTLCache(ttl_seconds=300)
```

### 8. Validation

```python
class PaymentRequest(BaseModel):
    amount: float = Field(gt=0, description="Payment amount")
    card: str = Field(min_length=13, max_length=19)
    
    @validator('card')
    def validate_card(cls, v):
        if not v.isdigit():
            raise ValueError('Card must be numeric')
        return v
```

**When to use:** Any user input, financial data, critical operations

### 9. Tool Composition


### 10. Context-Aware Tools

```python
class UserContext:
    def __init__(self):
        self.user_id = None
        self.cart = []

context = UserContext()

@tool
def add_to_cart(item: str) -> str:
    if not context.user_id:
        return "Error: Login required"
    context.cart.append(item)
    return f"Added {item}"
```

**When to use:** Stateful operations, authentication required, session management

## Decision Tree

### Should I use Pydantic?
- **Simple types (str, int, bool):** No, use type hints
- **Complex objects:** Yes
- **Validation needed:** Yes
- **Nested structures:** Yes

### Should I add retry logic?
- **External API calls:** Yes
- **Network operations:** Yes
- **Database queries:** Maybe (depends on failure mode)
- **Validation failures:** No

### Should I cache results?
- **Static data:** Yes
- **Expensive computations:** Yes
- **Frequent repeated queries:** Yes
- **User-specific data:** Be careful (cache by user)
- **Real-time data:** No

### Should I rate limit?
- **External API (with limits):** Yes
- **Expensive operations:** Yes
- **User-initiated actions:** Consider
- **Read-only queries:** Usually no

## Performance Tips

### Parallel Execution
✅ **Do:** Use for independent operations  
❌ **Don't:** Use when operations depend on each other

**Before (Sequential):** 3s  
```python
get_profile(user_id)    # 1s
get_orders(user_id)     # 1s
get_reviews(user_id)    # 1s
```

**After (Parallel):** 1s  
```python
# All three called simultaneously
```

### Caching
✅ **Do:** Cache expensive, repeated operations  
❌ **Don't:** Cache frequently changing data

**Savings:** 50-90% cost reduction on cached calls

### Rate Limiting
✅ **Do:** Protect expensive endpoints  
❌ **Don't:** Rate limit everything

**Balance:** Speed vs cost control

## Debugging Checklist

Tool not being called?
- [ ] Check tool docstring exists
- [ ] Verify parameter descriptions clear
- [ ] Test schema with direct call
- [ ] Check for ambiguous tool names

Tool called with wrong parameters?
- [ ] Use `Literal` for constrained choices
- [ ] Add examples in descriptions
- [ ] Validate with Pydantic
- [ ] Check type hints correct

Tool failing silently?
- [ ] Add `@safe_tool_execution` wrapper
- [ ] Return structured error responses
- [ ] Log all errors
- [ ] Test edge cases

Performance issues?
- [ ] Identify sequential operations that could be parallel
- [ ] Add caching for repeated queries
- [ ] Profile tool execution time
- [ ] Check for unnecessary API calls

### External API Tool
```python
@tool
@instrumented_tool

    """Call external API with retry logic."""
```
